# Известные проблемы

Список собран 2026-11-10 при подключении сервера к mcprig (набор `ha`). Каждый
пункт проверен живым вызовом или чтением кода; номера строк — по текущему
`main`/`api.py` в этом репозитории.

## P0 — ломает работу

### 1. `get_torrent_list` отдаёт весь список без параметров и пагинации

`main.py:223` — `async def get_torrent_list() -> str`, аргументов нет вообще.
`api.py:630` — `get_torrent_list_api()` делает GET `/api/v2/torrents/info` без
`limit`, `offset`, `filter`, `category`, `sort` и возвращает `response.json()`
целиком.

Замер на живой библиотеке: **996 423 байта**, 123 отдельных `TextContent` по
~6.6 КБ. Каждая запись несёт `magnet_uri` и до 88 трекеров — это и есть
основной вес. Вызывающий передаёт `limit: 5` — FastMCP молча выбрасывает
незнакомый аргумент, ответ тот же байт-в-байт.

Следствие: MCP-клиент получает ~1 МБ (mcprig режет до 32 768 байт и пишет файл,
но остальные клиенты — нет), контекст модели забивается мусором.

Что делать: параметры `limit` (по умолчанию 50), `offset`, `filter`
(`all|downloading|completed|...`), `category`, `sort`, `hashes`; проекция полей
(`name, hash, size, progress, state, dlspeed, upspeed, eta, ratio, added_on`) и
флаг `include_trackers`/`include_magnets`, по умолчанию выключенный. Возвращать
`{"total": N, "returned": M, "torrents": [...]}`.

### 2. Падение на `server/discover` убивает процесс

При MCP-ревизии `2026-07-28` клиент (go-sdk v1.8.0 и другие) первым шлёт
`server/discover` (SEP-2575). `mcp 1.9.0` (FastMCP) не знает метода и падает:

```
pydantic_core._pydantic_core.ValidationError: 24 validation errors for ClientRequest
Input should be 'ping' ... input_value='server/discover'
```

Трассировка — `mcp/shared/session.py`, `mcp/server/session.py` `_receive_loop`,
процесс выходит с `rc=1`, не ответив. Клиент ждёт до таймаута.

Следствие: любой современный клиент видит зависший сервер; в mcprig это
`context deadline exceeded` на `initialize`, без единой строки в логе (stderr
уходил в `/dev/null`).

Что делать: обновить `mcp[cli]` до версии, знающей ревизию, либо не падать на
неизвестном методе (ответить JSON-RPC error `-32601` и продолжать).

### 3. Ошибки возвращаются как успешный текст

`api.py:612-620` (`return "Login failed, unable to get SID"`), `api.py:640`
(`return f"Failed to get torrent list: status code {…}"`), `api.py:642`
(`return f"Error: {str(e)}"`) — тот же `return`, что и у нормального ответа.
MCP отдаёт это с `isError: false`.

Следствие: клиент не отличает отказ от данных, ретраев нет, статистика врёт.

Что делать: `raise ToolError(...)` (FastMCP) либо единый конверт
`{"ok": false, "error": {"code": "...", "message": "..."}}` для всех тулов.

## P1 — врёт или мешает

### 4. Логин считает успехом ответ без сессии

`api.py:24-32`: успех — любой `200`/`204`. qBittorrent на неверный пароль
отвечает `200` с телом `Fails.` и без cookie. Код возвращает пустую cookie jar,
дальше каждый тул падает на авторизации с невнятной ошибкой.

Что делать: проверять наличие `SID` в cookie и тело ответа (`Ok.`), иначе
возвращать ошибку авторизации один раз и явно.

### 5. Тип возврата не совпадает с аннотацией

`api.py:630` объявлено `-> str`, но на `200` возвращается `dict`/`list`, на
ошибке — `str`. Схема ответа тула меняется от вызова к вызову.

Что делать: один тип (`list[Torrent]`/dict) + отдельный путь для ошибок.

### 6. `delete_torrent` удаляет файлы без предпросмотра

`main.py:51` — `delete_torrent(hashes, delete_files: bool = False)`; при
`delete_files=true` файлы уходят безвозвратно, подтверждения и dry-run нет,
`hashes` — произвольная строка (`all` тоже принимается API).

Что делать: `dry_run: bool = true` по умолчанию либо отдельный тул
`preview_delete`, возвращающий список имён и размеров.

### 7. Неочевидные единицы у лимитов скорости

`main.py:104,117,167,181` — `limit: int` без описания: qBittorrent ждёт
**байт/с**, `-1` — без лимита, `0` — тоже «без лимита» в разных версиях.
Ошибка в 1000 раз принимается молча.

Что делать: принимать `limit_kbps` и переводить, либо явно писать «байт/с,
-1 = снять лимит».

### 8. Структурные аргументы завёрнуты в JSON-строку

`main.py:35` — `add_torrent(query: str)` ждёт JSON-строку с путями;
`main.py:140` — `set_file_priority(hash, id: str, priority: int)`, где `id`
строкой, а приоритет без проверки диапазона (0/1/6/7).

Что делать: `torrent_paths: list[str]`, `file_ids: list[int]`,
`priority: Literal[0,1,6,7]`.

### 9. `search_torrents`: жёсткий фильтр и top-10

`main.py:229-249`, `api.py:780-790`: результаты жёстко режутся по
`max_size_gb=5` и сортируются в top-10. Плагины поиска должны быть включены в
qBittorrent — если нет, приходит пустой список без объяснения.

Что делать: `max_size_gb: float | None = None`, `limit: int = 10`, отличать
«нет плагинов» от «нет результатов», добавить `plugins_status`.

### 10. Китайские docstring’и в англоязычном коде

`main.py:239-248` (`搜索种子`, `搜索关键词`), `api.py:673` — описания тулов
уходят в схему MCP, модель читает их как есть.

Что делать: перевести на английский (или на русский, но единообразно).
